AI Stack

Sistem memakai tiga lapis kecerdasan: deteksi visual (YOLOv8), forecasting time-series (Transformer + fallback statistik), dan agen percakapan (Ollama LLM opsional). Tiap lapis bisa dijalankan sendiri sesuai kebutuhan.

1. Perception

YOLOv8 (Ultralytics) atau fallback ONNX via OpenCV DNN. Mendeteksi class car dan motorcycle dengan NMS + IoU tracking custom.

2. Forecasting

Tiny Transformer encoder (PyTorch) dilatih per kamera dari 60 hari history. Fallback ke rata-rata DOW × Hour kalau data belum cukup.

3. Assistant

LLM lokal (Ollama, mis. mistral:7b) bertindak sebagai agent: jawab pertanyaan dan eksekusi ui_actions di frontend.

Kenapa pakai IoU Tracker

Detektor objek stateless — di setiap frame, YOLO cuma mengembalikan kotak pembatas tanpa tahu kotak yang sama sudah muncul di frame sebelumnya. Kalau kita hanya menjumlahkan hasil deteksi mentah, mobil yang berhenti di lampu merah akan terhitung puluhan kali. Tracker mencocokkan deteksi baru dengan track lama memakai rasio Intersection over Union. Hanya track baru yang menambah accumulated_count.

Threshold tuning. Default track_iou_threshold = 0.30 dan track_ttl_s = max(3s, PROCESS_INTERVAL × 4). Naikkan IoU untuk menghindari false merge di persimpangan ramai; turunkan TTL supaya track lama cepat expire saat lalu lintas cepat.

Primary: Tiny Transformer Forecaster

Implementasi ringkas di app/database.py. Satu model per kamera, disimpan di memori.

1

Bangun seri per jam. Query 60 hari terakhir, bucket ke hourly totals di timezone lokal.

2

Normalisasi. Hitung mean & std, ubah tiap nilai ke z-score supaya pelatihan stabil.

3

Encode fitur. Setiap timestep di-embed memakai hour_embedding (24), dow_embedding (7), pos_embedding, lalu dijumlahkan dengan proyeksi linear nilai.

4

Encoder self-attention. 2 layer TransformerEncoder, d_model 32, 4 attention head, dropout 0.1.

5

Head linear. LayerNorm + Linear(32 → 1) mengembalikan prediksi z-score.

6

Inference. 48 jam history terakhir dikirim ke model, output di-denormalisasi kembali ke jumlah kendaraan.

# Arsitektur model (disederhanakan) 
class _TinyTransformerForecaster(nn.Module):
    def __init__(self, d_model=32, nhead=4, num_layers=2, dropout=0.1, max_len=256):
        super().__init__()
        self.value_proj = nn.Linear(1, d_model)
        self.hour_emb   = nn.Embedding(24, d_model)
        self.dow_emb    = nn.Embedding(7,  d_model)
        self.pos_emb    = nn.Embedding(max_len, d_model)
        enc = nn.TransformerEncoderLayer(d_model, nhead, dropout=dropout, batch_first=True)
        self.encoder = nn.TransformerEncoder(enc, num_layers=num_layers)
        self.head    = nn.Sequential(nn.LayerNorm(d_model), nn.Linear(d_model, 1))

    def forward(self, x_val, x_hour, x_dow):
        pos = torch.arange(x_val.size(1), device=x_val.device)
        h = self.value_proj(x_val) + self.hour_emb(x_hour) + self.dow_emb(x_dow) + self.pos_emb(pos)
        return self.head(self.encoder(h)[:, -1, :])
Kapan model dilatih? Saat permintaan prediksi pertama kali, sistem mengecek apakah kamera sudah punya model. Kalau belum dan data mencukupi (≥ max(context_len+24, 96) bucket jam), trainer dijalankan di thread background. Sampai training selesai, request dijawab lewat fallback di bawah.

Fallback: DOW × Hour Average

Strategi statistik sederhana yang tidak butuh PyTorch. Sistem menghitung rata-rata jumlah kendaraan untuk pasangan (day-of-week, hour) yang sama di seluruh riwayat.

-- Query PostgreSQL yang dipakai (app/database.py) 
WITH hourly_sums AS (
    SELECT DATE(to_timestamp(timestamp) AT TIME ZONE 'Asia/Jakarta') AS date_str,
           SUM(new_count) AS hourly_total
    FROM traffic_history
    WHERE camera_id = $1
      AND EXTRACT(DOW FROM to_timestamp(timestamp) AT TIME ZONE 'Asia/Jakarta') = $2
      AND EXTRACT(HOUR FROM to_timestamp(timestamp) AT TIME ZONE 'Asia/Jakarta') = $3
    GROUP BY date_str
)
SELECT AVG(hourly_total) AS avg_hourly_traffic
FROM hourly_sums;

Alur Training (On-the-fly)

1

Trigger. Saat user pertama kali minta prediksi untuk kamera X dan belum ada model di memori.

2

Query data. Ambil 60 hari terakhir dari traffic_history, bucket ke hourly SUM(new_count).

3

Cek minimum. Butuh minimal 96 bucket jam (~4 hari kontinu). Kalau kurang → fallback DOW×Hour.

4

Normalisasi. Hitung mean & std dari seluruh series, ubah ke z-score.

5

Sliding window. Buat pasangan (input 48 jam, target 1 jam berikutnya) untuk semua posisi.

6

Training. 6 epoch, batch 64, AdamW, gradient clipping 1.0. Selesai dalam 2–5 detik di CPU.

7

Cache. Model disimpan di RAM per kamera. Hilang saat restart, dilatih ulang otomatis.

Multi-step autoregressive: Untuk prediksi N jam ke depan, model dijalankan N kali. Setiap step, hasil prediksi dimasukkan ke window sebagai input step berikutnya. Contoh: target 11 jam → model jalan 11 kali berurutan.

Kenapa Self-Attention Cocok untuk Traffic

Self-attention memungkinkan model melihat semua 48 jam sekaligus dan belajar korelasi jarak jauh:

  • Pola harian: Jam 8 pagi hari ini mirip jam 8 pagi kemarin (jarak 24 jam)
  • Pola mingguan: Senin jam 8 mirip Senin minggu lalu (ditangkap lewat DOW embedding)
  • Transisi: Kalau jam 7 mulai ramai, jam 8 kemungkinan puncak (korelasi pendek)
  • Weekend vs weekday: DOW embedding otomatis membedakan pola Sabtu/Minggu

Kode Inti (Ringkas)

# Training (app/database.py → _get_or_train_transformer)
series = query_60_days_hourly(camera_id)     # [(ts, count), ...]
mean, std = compute_stats(series)

for epoch in range(6):
    for batch in sliding_windows(series, context=48):
        x_val = normalize(batch.values)       # shape: [B, 48, 1]
        x_hour = batch.hours                  # shape: [B, 48]
        x_dow = batch.dows                    # shape: [B, 48]
        y_true = normalize(batch.target)      # shape: [B, 1]

        y_pred = model(x_val, x_hour, x_dow)  # forward pass
        loss = MSE(y_pred, y_true)
        loss.backward()
        optimizer.step()

# Inference (app/database.py → _predict_with_transformer)
window = last_48_hours()
for step in range(hours_ahead):
    pred = model(window)                      # 1 step
    window = window[1:] + [pred]              # slide window
return denormalize(pred)                      # → kendaraan/jam

WITH hourly_sums AS (
    SELECT
        DATE(to_timestamp(timestamp) AT TIME ZONE 'Asia/Jakarta') AS tgl,
        SUM(new_count) AS hourly_total
    FROM traffic_history
    WHERE camera_name = 'Simpang Braga'
      AND EXTRACT(DOW FROM to_timestamp(timestamp) AT TIME ZONE 'Asia/Jakarta') = 3
      AND EXTRACT(HOUR FROM to_timestamp(timestamp) AT TIME ZONE 'Asia/Jakarta') = 8
    GROUP BY tgl
)

    AVG(hourly_total)::int AS prediksi_kendaraan_per_jam,
    COUNT(*) AS jumlah_sample,

        WHEN AVG(hourly_total) > 2000 THEN 'MACET TOTAL'
        WHEN AVG(hourly_total) > 1000 THEN 'MACET'
        WHEN AVG(hourly_total) > 500  THEN 'PADAT LANCAR'
        ELSE 'LANCAR'
    END AS status_prediksi
FROM hourly_sums;

FAQ

Kenapa prediksi kadang jatuh ke DOW-Hour Average?

Transformer hanya dilatih kalau sudah ada minimal 96 bucket jam (~4 hari kontinu) dan PyTorch terpasang. Kalau salah satu syarat gagal, sistem otomatis pakai rata-rata DOW × Hour supaya tetap memberi jawaban.

Bagaimana cara sistem menghindari double counting di lampu merah?

Setiap deteksi YOLO dicocokkan ke track yang sudah ada lewat rasio IoU. Kalau cocok, track itu di-refresh (bukan dihitung ulang). Hanya track baru yang menambah akumulator.

Apakah sistem bisa jalan tanpa GPU?

Bisa. Fallback ke OpenCV DNN (ONNX) yang dioptimasi untuk CPU. Kecepatan turun tapi tetap real-time untuk ~10 stream.

Kenapa pakai PostgreSQL, bukan SQLite?

PostgreSQL mendukung concurrent writes dari 37 camera agents tanpa file-locking. Juga lebih scalable untuk production deployment, mendukung connection pooling, dan punya built-in date/time functions yang kaya untuk query prediksi.

Kalau kamera offline, data tetap ada?

Ya. Agent akan beralih ke simulasi pola lalu lintas berbasis jam. Status kamera ditandai offline agar dashboard tidak menipu.
